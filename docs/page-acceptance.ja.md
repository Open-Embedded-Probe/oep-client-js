# OEP Probe Tool — 受入条件

状態: [画面仕様](page.ja.md)と[接続引継ぎ仕様](page-connection.ja.md)の判定基準。
仮想プローブでの試験の成功を、実機での達成とは扱わない。

## 1. 場面ごとの受入条件

画面と場面の番号は[画面仕様](page.ja.md)のもの。

| ID / 場面 | 操作・条件 | 合格条件 |
| --- | --- | --- |
| A01 / — | 未接続でスタート（S1）を開く | このページですること、作る・つなぐの入口、用途ごとの準備と道具、資料が読める。機器の許可を求めない |
| A02 / U2 | 未接続でプローブのタブ（P1〜P6）を開く | つなぐ案内（S3）へ進み、接続後に同じタブへ戻る |
| A03 / U1 | ボードを比べる（S2） | 推奨ボード、導入方法、配布firmware／このページでの導入／実機検証を区別して見られる。型番だけの選択欄ではない |
| A04 / U1 | 未導入のclassic ESP32をシリアルから作る | 機器の選択1回で、書込→起動確認→プローブの概要へ。方式の選択、追加の機器選択、切断操作は0回 |
| A05 / U1 | P4/P4XをUSB-Serial/JTAGから作る | revisionに合うイメージで書き、同じ端子で続く。HSへの変更を求めない |
| A06 / U1 | P4の外付けUART bridgeから作る | CDCと同じ画面・操作で続く。追加の方式選択・機器選択は0回 |
| A07 / U1 | 未導入のPico/Pico 2を作る | BOOTSELから再列挙・許可を経てプローブの概要へ。機器が現れないときは抜き差しを案内し、書込結果を保つ |
| A08 / U1 | 同型の別プローブもつないで書込後に再列挙 | 別個体を自動で開かない |
| A09 / U1 | 書込は成功したがOEPの応答が遅い・無い | 書込成功と待機・失敗を区別し、書き直さずに同じ端子で再試行できる |
| A10 / U2 | 導入済みの機器につなぐ | ボードの種類を選ばせない。読んだunit_id・model・宣言で画面を作る |
| A11 / U2 | つなぎ方を選ぶ | USBシリアル・USB（OEPの機器）・USB HIDの違いが、どのボードがどれを使うかで分かる。画面に「口」などの分かりにくい用語を使わない |
| A12 / U2 | 概要（P1）を開く | 個体、ファームと配布版の比較、経路、次にすること、宣言された機能が分かる |
| A13 / U4 | ターゲット未接続でデバッグ＋UARTの配線を作る | 名前・型番・メモ・複数信号を保存できる。ATTACH・PLAN_APPLY・出力を呼ばない |
| A33 / U4 | 接続名や信号名を打つ | 誤りがその場で、どの欄の何が悪いかとともに出て、誤りがある間は保存できない。名前の前後の空白は誤りにしない |
| A14 / U4 | 既存の配線の名前・型番・ピンを直す | ほかの信号と未知のメモの項目を保つ。古い名前と配線を残さない |
| A15 / U4 | キャンセル、画面移動、言語変更、保存の競合 | キャンセルは明示的に破棄。ほかは入力を保ち、競合では差分を確かめる |
| A16 / U3,U4 | メモ非対応・永続保存非対応・保存の途中失敗 | 保存先、今回だけの適用、途中までの成功を区別する |
| A17 / U3 | 本体設定を適用する | その場で効き、プローブの帯に未保存と「保存」が出る。保存すると消える |
| A18 / U3 | Wi-Fiの無いプローブ | SSIDを入力させず、失敗と表示しない |
| A19 / U3 | 素通しを設定する | 適用・保存でき、道具へ渡す（P5）のログに出る。相手→PCの一方向で、相手へは送らない |
| A20 / U3 | USBの経路を変える | 宣言された組み合わせだけを選べ、保存して再起動し、つなぐ（S3）で選び直す |
| A21 / U4 | ピンを指定して接続確認 | 未確認・応答なしでも保存できる。方式・ピンを変えると結果が消える。結果は保存しない。確認の接続はその場で終える |
| A22 / U4 | デバッグの配線を登録する | restはSWCLK、holdはSWDIOの本体設定と区別する |
| A23 / U5 | 道具へ渡す（P5）を開く | 用途の順に道具と、この個体・登録した配線のアドレス、コマンドが出る。このページで作業ができるとは書かない |
| A24 / U5 | このページでの利用を終えて渡す | 明示の操作で変更権と接続を解放する。資料を読むだけでは切らない |
| A25 / U1 | ファームを更新する | 対象と方式を確かめ、更新後は同じ個体を選び直す |
| A26 / U3 | 設定・メモを控えて戻す | 1つのOEPの設定のファイルに入る。秘密の値を含めない。戻す前に差分（別の個体、値、書く・消すメモの記録、無い項目、秘密の値の不足）を見せる |
| A27 / U2 | 接続中にケーブルを抜く・プローブが再起動する | その場で「接続が切れました」と理由を出し、接続中の表示を残さない。もう一度つなぐと同じ画面へ戻り、読み直す。書換えを自動で送り直さない |
| A28 / — | 他のアプリが変更権を持つ | 持ち主と再試行を示す。強制しない |
| A29 / — | 狭い画面、キーボード、日英、直接のURL | 主な操作が使え、入力を失わない |
| A30 / — | 秘密の値と診断の出力 | 秘密の値が出力や控えに入らず、機器の文字列がHTMLとして実行されない |
| A31 / U1 | S3等のCDC/boot構成からOEPのUSB構成へ切り替わる | 起動後の端点へ移り、自動再列挙で続けば抜き差しを求めない。新しい許可は同じ画面で取る |
| A32 / U1 | 構成変更後にOEPが一覧に現れず、抜き差しで認識される | 書込成功を保って案内し、再書込・方式選択を挟まず、別個体を自動で開かない |

「機器の選択」はブラウザのchooserを開いた回数。「方式の選択」はUSB/Serial/HIDを利用者に決めさせる操作の回数。

## 2. 試験の扱い

`npm run typecheck` と `npm run test:browser`（Python仮想プローブとChromium）で、型、サイトのビルド、§3.1の流れを確かめる。
API呼出しの有無、別個体への誤接続、部分成功、入力保持を確かめ、文言の一致だけの試験で済ませない。
書込・USB再列挙・電気的な状態は、ブラウザの試験と実機の確認を分けて報告する。

## 3. 状況

### 3.1 仮想プローブとChromiumで確かめたもの

| 範囲 | 確かめたこと |
| --- | --- |
| スタート（S1） | 機器の許可なしに読める。作るが主な入口。用途の表（A01）。旧URLは新しい画面へ移る（§4） |
| 作る（S2） | ESP32のROMからチップを読み、書き、同じポートでOEPを開いて概要へ（A04）。再接続できないときは書き直さずに再試行（A09）。PicoはBOOTSELの機器を1回選んでUF2を書き、新しく現れたOEPの機器を開く（A07） |
| つなぐ（S3） | 未接続で開いたタブへ、接続後に戻る（A02） |
| 概要（P1） | 導入の直後に「導入できました」と次にすること（A12） |
| 配線（P2、P3） | デバッグのピンを選ぶと接続確認のボタンが使えるようになる。接続名の誤り（英字で始まらない、使えない文字、重複）がその場で出て保存が止まる。相手側のピン名の前後の空白は外し、中の空白はどの信号かを書いて止める（A33）。種類の選択は無く、型番を空けた配線は「差し替えて使うコネクタ、または未記入」と出る。相手の無いまま、UARTと独自の信号を保存し、attach・ピンの割当をしない（A13）。型番・メモと種類はメモ領域へ。型番を直してもデバッグの線は残る（A14）。接続確認の結果は保存しない（A21） |
| 本体設定（P4） | 素通しを適用し、帯の「保存」で保存し、道具へ渡すに出る（A17、A19）。ピンの待機状態を適用・保存。Wi-Fiを適用し、秘密の値を表示しない（classic ESP32） |
| 道具へ渡す（P5） | 登録した配線のアドレス。利用を終えて渡すと接続を終えてスタートへ（A24） |
| 保守（P6） | 設定とメモを1つのファイルに控え、差分を見てから戻す。消したメモの記録も戻る（A26）。宣言を読み直す。PicoをUSBからboot ROMへ切り替えて更新、P4を同じ個体のDFUで更新（A25） |
| 接続の切断 | 経路がひとりでに閉じると、今いる画面に理由ともう一度つなぐ入口が出て、つなぎ直すと同じ画面へ戻る（A27） |
| 共通 | 390px幅で横にはみ出さない。日英の切り替えで入力・画面・接続を保ち、覚える。英語の全画面に日本語が残らない。画面のリンクに行き先の無いものが無い（A29） |

画面にあって、仮想プローブの試験でまだ通していないもの: P4・S3のUSB再列挙と許可（A31、A32）、SWDの接続確認（RP2040のmultidropを含む。
仮想プローブにSWDのprofileが無い）、USBの経路と保存して再起動（profileがusb.transportsを宣言しない）。ブラウザの書き込み・DFU・boot ROMの処理そのものは
試験では偽物で、実機で別に確かめる。
接続確認の「相手の識別」は、応答した値（RISC-VのDMSTATUSかSWDのDPIDR）を出すところまで。

### 3.2 公開を判断する前に確かめること

| 検証事項 | 必要な証拠 | 結果が不十分な場合 |
| --- | --- | --- |
| ESP32同一ポートの継続 | 配布ファームウェアイメージ・実機・OS/ブラウザごとに、書込後のchooser回数とOEP確認結果 | 該当組合せを未確認として表示。対応済みとしない |
| P4/P4Xの経路 | 既定有効化されたUART bridgeが配布ファームウェアイメージに反映されたこと、USB-Serial/JTAG/外付けUARTの両方で同じUIから継続できる実機試験、revision照合 | 配布への反映と経路別の検証を完了させる。Webの通常フローにCDC/UARTの選択や端子変更を追加して回避しない |
| RP2/S3等のUSB構成変更 | boot/CDCからOEPへのidentity・機能・許可の対応、同型複数台、自動再列挙と抜き差しが必要な環境の区別 | 同一性が不明なら対象を限定して許可を取得。抜き差しで復旧する条件を記録し、書込結果を保持して設定へ続行 |
| 再列挙・権限・reset信号 | 対応OS/ブラウザでのタイミング、許可取消、抜線、DTR/RTSの挙動 | 自動継続を約束する範囲を限定し、同じ画面での復旧を提供 |
| 新規書込と更新の設定保持 | 配布ファームウェアイメージの書込範囲と保存領域、更新前後の設定比較 | 「保持する」と断言せず、控え・復元または消去の説明 |
| 初見での理解 | OEPを知らない人が、スタートからプローブの作成、配線の登録、道具へ渡すまでを画面だけでたどれるか | 文言・順序を修正。テストが通ることだけで分かりやすいと判断しない |

仕様の方向性と上記の検証結果は分ける。ハードウェア未確認を文面だけで「解決済み」にしない。
