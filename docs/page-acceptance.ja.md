# OEP Web — 受入条件・実装との差分

状態: [画面要件](page.ja.md)と[接続引継ぎ仕様](page-connection.ja.md)の判定基準。
ここに並ぶ条件は、現行画面がすべて満たすという意味ではない。
仕様文書に加え、独立した[操作プレビュー](page-preview.ja.md)で画面構成と遷移を確認する段階。実機検証は含まず、プレビューの試験成功を以下の受入条件全体の達成とは扱わない。

## 1. 仕様として今回決めること

- OEPの公開入口と、接続した個体の作業領域を分け、相互に行き来できる構成にする。
- 初回訪問で概要・用途・ボード・技術を理解でき、詳細は各OEP側文書を正として案内する。
- 新規プローブ作成を主導線にし、導入済み利用もすぐ始められる。
- 書込から設定は一つの作業。内部の通信切替を理由に利用者へ方式・ボード種類を選び直させない。
- 初期設定は目的別。配線登録だけを唯一の出口にせず、本体設定・復元・すぐ試す・あとで設定を用意する。
- 配線は相手未接続でも作成・編集可能。スキャンは補助操作。保存しても動作は始めない。
- 機能の画面は目的・配線・条件・開始・結果・終了を一体で扱う。
- 外部ツールへ任せる機能と、そのために必要な環境を明示する。

## 2. 利用者視点の受入シナリオ

| ID / 対応要件 | 操作・条件 | 合格条件 |
| --- | --- | --- |
| A01 / R01 | 未接続・初回訪問で入口を読む | OEPの役割、host/probe/相手の関係、用途、ボード、技術資料が分かる。機器許可を求めない |
| A02 / R01,R02 | 「UARTログを読みたい」から開始 | 必要なもの・配線・結果が分かり、導入か既存機器接続を経て同じ用途へ到達する |
| A03 / R01,R03 | 複数のボードを比較 | 選択肢と特徴が見え、firmware配布/ブラウザ導入/実機検証を区別できる。型番だけの選択欄ではない |
| A04 / R03,R04 | 未導入classic ESP32をシリアルから作成 | 初回の機器選択1回で、書込→起動確認→初期設定へ。通常経路の追加の方式選択・機器選択・切断操作は0回 |
| A05 / R03,R04 | P4/P4XをUSB-Serial/JTAGから作成 | 適合revisionのファームウェアイメージを使い、同じ端子で設定できる。HSへの変更を必須にしない |
| A06 / R03,R04 | P4の外付けUART bridgeを選ぶ | CDC系の経路と同じ画面・操作で、元のポートから設定へ進む。CDC/UARTの分類情報がなくても続行し、追加の方式選択・機器選択・切断操作は通常経路で0回 |
| A07 / R03,R04 | 未導入Pico/Pico 2を書込 | BOOTSELからOEPへの再列挙・必要な許可を経て初期設定へ。起動後の機器が現れない場合は同じボードの抜き差しを案内し、書込結果を保持して続行 |
| A08 / R04,R09 | 同型の別プローブもつないで書込後に再列挙 | 別個体を自動で開かない。同一性が確認できない場合は対象の許可を求める |
| A09 / R04,R09 | 書込は成功したがOEP起動が遅い/応答しない | 書込成功と待機/失敗を区別。入力と対象を保持し、同じ端子で再試行できる。再書込を強制しない |
| A10 / R05 | 導入済みの機器を使う | 接続前のboard選択なし。読んだunit_id/model/機能で画面を構成。呼出元の作業へ戻る |
| A11 / R05 | 履歴なしでUSB専用プローブを接続 | シリアル一覧にない場合の案内からOEP USBへ進める。ボード名入力やUSB/Serial/HIDの知識を要求しない |
| A12 / R06 | 新規導入後に「あとで設定」「すぐ試す」を選ぶ | 配線登録やネットワーク設定をしなくても終了/作業開始できる |
| A13 / R06,R07 | ターゲット未接続でdebug+UARTの配線を作成 | 名前・相手型番・メモ・複数信号を保存できる。SCAN/ATTACH/PLAN_APPLY/出力操作を呼ばない |
| A14 / R07,R09 | 既存配線の名前・型番・UARTピンを編集 | 既存debug信号と未知のメモ項目を保持。他の接続先を変えず、古い名前と配線の残骸を残さない |
| A15 / R07,R09 | キャンセル、画面移動、言語変更、保存競合 | キャンセルは明示的に破棄。その他は入力を保持し、競合では差分確認へ。別個体へ自動適用しない |
| A16 / R07,R09 | メモ非対応/永続保存非対応/保存途中失敗 | 保存先・今回だけの適用・途中成功を区別。全保存成功と誤表示せず、該当工程から復旧できる |
| A17 / R08 | 保存済み配線を操作画面へ呼び出す | 入力だけを反映。開始まで接続・出力・転送を実行しない |
| A18 / R08 | UARTで受信開始→送信→停止 | RX/TX方向、通信条件、ログ、エラー、停止後の状態を一画面で追える |
| A19 / R08 | I2C/SPIのcontrollerと相手機器役をそれぞれ使う | 誰がclock/要求を出すかが説明され、入力・転送/待受・結果・終了が完結する |
| A20 / R08 | GPIO/PWM/counter/DACを使う | 入力範囲・単位・継続/単発が分かる。計測値と設定値を混同せず、継続出力を止められる |
| A21 / R08 | 固定配線でdebug接続→制御→console→切離し | 探索を経ず操作でき、応答した相手と停止/実行状態が分かる。メモ上の型番を識別結果にしない |
| A22 / R08,R09 | debugとUARTの併用、同一ピンの競合 | 共存可能な操作は維持。競合時は使用者と対処を示し、勝手に他の操作を停止しない |
| A23 / R06,R09 | 待機ピン・Wi-Fi・起動時設定を変更 | 意味と適用タイミング、保存状態が分かる。非対応項目は入力させない |
| A24 / R09 | 動作中に抜線/再起動/セッション喪失 | 状態の不確実性を表示。再接続後に読込をやり直し、書換えや出力を自動再送しない |
| A25 / R09 | 他アプリが変更権を保持 | 所有者/使用中状態と再試行を示す。forceしない |
| A26 / R10 | 波形の画面から外部へ進む | ファイル表示と取得環境を区別。必要な個体・配線情報と資料がある。公開Viewerだけで取得できると表示しない |
| A27 / R10 | IDE/Pythonへ機器を引き渡す | 明示操作で作業と通信を終了して渡す。資料閲覧だけでは切断しない |
| A28 / R09 | firmware更新または設定復元 | 対象、保持/消去、差分と未対応項目を確認。更新後の同じ個体・版を確認し、元の作業へ戻れる |
| A29 / R01,R09 | 狭い画面、キーボード、日英、深いURL | 説明と主操作が使え、入力/目的を失わず、機器がなくても説明は読める |
| A30 / R09 | パスワード等の設定と診断ログ出力 | 秘密値がログや共有情報に含まれず、機器からの文字列もHTMLとして実行されない |
| A31 / R03,R04,R09 | S3等のCDC/boot構成からOEPのVID/PID・USB機能へ切り替わる | 元のSerialPortに固執せず、起動後の端点へ移行。自動再列挙で続行できれば抜き差しを要求しない。新規許可は同じ導入画面で取得 |
| A32 / R04,R09 | USB構成変更後にOEPがchooserに現れず、抜き差しで認識される | 書込成功を保った案内→同じボードを抜き差し→必要な許可→設定。再書込・方式選択を挟まず、別個体を自動で開かない |
| A33 / R04,R09 | 同じシリアル端点を維持するファームウェアイメージ、またはCDCを含むOEP複合USB構成 | 型番だけでCDC消滅やWebUSBへの移行を決めつけない。存続する経路を再利用し、変更があればファームウェアイメージの構成と実機に従う |

追加の用途別受入条件（[ガイドレビュー](page-guide-review.ja.md)）:

| ID | 操作・条件 | 合格条件 |
| --- | --- | --- |
| A34 | 今回だけロジック取得 | 配線名・本体設定なしでピンと取得条件を準備できる |
| A35 | 登録済みdebug/UART配線をロジック観測 | 既存名で選択でき、新しい配線登録やピンの奪取を要求しない。analogの専有とは区別 |
| A36 | 通常UART、console、素通しを選ぶ | 操作条件と本体設定を区別。UARTはRXのみで使え、sdi/素通しには送信を出さない |
| A37 | 据え置き治具を用意 | 使用禁止→配線名→待機→任意素通し→保存・控えの順をたどれる |
| A38 | プローブにWi-Fi設定がない | SSIDを入力させず、導入失敗とは表示しない |
| A39 | デバッグ配線を登録・使用 | 速度上限は操作時に指定。restはSWCLK、holdはSWDIOの本体設定と区別。NRSTを使う接続とデバッグ線からのシステムリセットを混同しない |
| A40 | 公開用途から導入・接続する | 必要なもの・結果・Web/外部ツールの役割を未接続で読める。選んだ用途を導入後の準備へ引き継ぎ、ボード選択への戻り・再許可・抜き差し・再試行でも保持する。既存機器接続では導入の進行表示を挟まない |
| A41 | 導入前に用途を変更する | 用途を選び直せる。汎用の導入入口からやり直した場合は古い用途へ遷移しない |
| A42 | デバッグの配線を決める | 自動検索/ピン明示の2入口。検索は方式・候補ピンを決めて開始し、検索結果も手入力と同じ編集画面へ。自動保存しない |
| A43 | ピンを指定して任意の接続確認を行う | 未確認・応答なしでも保存できる。方式・ピン・NRST変更で確認結果は無効。確認結果は配線として保存しない。保存せず操作する場合もピンを引き継ぎ、動作を自動開始しない |

「機器選択の回数」はブラウザのchooserを開いた回数。「方式選択」はUSB/Serial/HIDを利用者に決めさせる操作の回数。
ROM移行用のBOOT等の物理操作は別に計測し、ボード案内で事前に示す。
同一端点を維持できる経路と、USB identity/構成が変わる経路は別に計測する。許可・抜き差しの必要回数を記録し、通常経路の追加操作0回の実績に混ぜない。

## 3. 実装・検証に残る事項

### 3.1 現行実装との差分

基準: `oep-client-js 408b49b`。すでにある処理は部品として利用できるが、現行画面を新仕様の正にしない。

| 項目 | 現行にあるもの | 次の実装で必要な変更 |
| --- | --- | --- |
| OEPの入口 | home/help/board紹介の分散した情報 | 公開入口の文案・用途・技術概要・資料導線を§3の構成へ |
| 全体ナビゲーション | 全体共通の導入→設定→使用レール | 公開部分と作業領域を分け、進行表示を導入作業に限定 |
| 導入後の接続 | `continueSetup`、同じSerialPortで接続試行 | 導入文脈を一元化し、短い再試行後に一般chooserへ落ちる構造を改める。経路別待機・許可・同一性を検証 |
| 新規ESP導入 | ボード指定後にROM検証・書込 | 検出できるチップ/revisionの選択を省略し、必要な基板差だけ確認。最初の配線を案内し、CDC/UARTの判別は要求しない |
| 導入済みの接続 | USB既定、詳細にSerial/HID | 履歴・導入文脈・資料の経路を優先。文脈なしの主入口と「一覧にない」の案内を仕様化 |
| 初期設定 | 主に接続先一覧 | 配線、本体設定、復元、すぐ試す、あとで設定の目的別入口へ |
| 配線編集 | 名前/型番/メモ/固定ピンの共通フォーム | 複数信号の明示編集、呼出元への復帰、差分と保存状態を整理 |
| 機能操作 | 公開APIを呼ぶフォームと結果 | 用途別の説明・配線・条件・開始/結果/停止を統合。raw値を適切な単位で扱う |
| 本体設定 | schemaベースの設定フォーム | 待機・起動・network等の意味と効果を説明し、適用と永続保存を明確化 |
| 外部連携 | WireSkeinやCLIへの案内 | ファイル表示と取得の区別、使用終了して渡す操作、引継ぎ情報を整備 |

### 3.2 公開を判断する前に確かめること

| 検証事項 | 必要な証拠 | 結果が不十分な場合 |
| --- | --- | --- |
| ESP32同一ポートの継続 | 配布ファームウェアイメージ・実機・OS/ブラウザごとに、書込後のchooser回数とOEP確認結果 | 該当組合せを未確認として表示。対応済みとしない |
| P4/P4Xの経路 | 既定有効化されたUART bridgeが配布ファームウェアイメージに反映されたこと、USB-Serial/JTAG/外付けUARTの両方で同じUIから継続できる実機試験、revision照合 | 配布への反映と経路別の検証を完了させる。Webの通常フローにCDC/UARTの選択や端子変更を追加して回避しない |
| RP2/S3等のUSB構成変更 | boot/CDCからOEPへのidentity・機能・許可の対応、同型複数台、自動再列挙と抜き差しが必要な環境の区別 | 同一性が不明なら対象を限定して許可を取得。抜き差しで復旧する条件を記録し、書込結果を保持して設定へ続行 |
| 再列挙・権限・reset信号 | 対応OS/ブラウザでのタイミング、許可取消、抜線、DTR/RTSの挙動 | 自動継続を約束する範囲を限定し、同じ画面での復旧を提供 |
| 新規書込と更新の設定保持 | 配布ファームウェアイメージの書込範囲と保存領域、更新前後の設定比較 | 「保持する」と断言せず、控え・復元または消去の説明 |
| 用途別フォームの値と停止 | 機能宣言を変えた仮想probe、継続出力/空き状態の実機試験 | 未対応項目を動作可能に見せない |
| 初見での理解 | OEPを知らない人が、入口の説明からプローブの作成、初期設定、U-Aの配線の登録までを説明と画面だけでたどれるか | 文言・順序を修正。テストが通ることだけで分かりやすいと判断しない |

仕様の方向性と上記の検証結果は分ける。ハードウェア未確認を文面だけで「解決済み」にしない。
本書の仕様レビュー後、公開情報→導入/接続→初期設定/配線→各用途/保守の順で実装を分ける。
段階ごとに対応するA項目を検証し、最後にU02とU03を通して確認する。

## 4. 既存画面からの移行

URLは利用者のブックマークを壊さず受け付ける。新画面の構成を旧route名に拘束しない。

| 旧URL | 新仕様での到達先 |
| --- | --- |
| `#home`, `#help` | P01/P04。接続があれば作業へ戻る入口を維持 |
| `#firmware` | 未接続の新規導入はI01。接続済みの更新目的はW06として案内 |
| `#connect` | C01。復帰先がなければ接続後W01 |
| `#setup` | I02。既存の個体なら現在設定を読んで表示 |
| `#probe` | W01 |
| `#targets`, `#target/new`, `#target/edit/<name>` | W02/W03。呼出元の文脈を保持 |
| `#signals/<function>`, `#debug` | 対応するW04。未接続でも用途の説明とC01を表示 |
| `#settings` | W05 |
| `#storage`, `#diagnostics` | W06の該当詳細 |
| `#tools` | W07 |

## 5. 文書・試験の扱い

実装変更時には既存の型検査・回帰試験とサイトビルドを行い、仮想probeとChromiumでA項目を検証する。
API呼出しの有無、別個体への誤接続、部分成功、入力保持などを検証し、文言の一致だけの試験で済ませない。
書込・USB再列挙・電気的な停止状態は、ブラウザのmock試験と実機試験を分けて報告する。

現在のプレビューでは `npm run typecheck` と `npm run test:preview` で型、サイトビルド、Chromiumでの画面遷移・編集・狭い画面での表示を確認する。
実機APIの呼出しや通信・書込モジュールの読込が発生しないことも検査する。仮想probeとの通信や実機の再列挙・権限の検証は、実処理を組み込む段階で行う。
