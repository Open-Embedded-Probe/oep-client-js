# 用途別ガイドのレビューとWeb画面への反映

2026-11-07。参照: `oep-probe-arduino` の `8742184`（用途別ガイド追加）、`7ab27fa`（CH32のリセット説明）、`7339c3a`（P4 UART bridge既定有効化）。規範との照合は `oep-spec f3709f8`。
ガイドの用途・設定の分類をWeb製品へ適用するためのレビュー。実機の対応確認や、全画面の受入完了を意味しない。

## レビューの結果

用途ごとの準備、配線、設定、操作、外部ツールの役割が整理され、画面の流れを決める根拠として使える。
特に「本体設定」「メモ」「操作の条件」「セッション中のピン割当」を分ける説明に従い、従来の試作で配線編集に並べていた速度・取得条件を操作側へ移す。

### ガイド側で修正が必要な点

| 優先度 | 記述 | 照合結果と影響 |
| --- | --- | --- |
| 高 | settings.ja.md「デバッグの線」の `channel.<SWDIO のピン>.rest` | キーは **SWCLK**。`oep-spec/interfaces/oep-if-debug.ja.md` §3.1と `src/OepSettings.cpp` の `Settings::restOf(..., swclk)` が一致している。SWDIOをキーにすると意図したクロックの待機状態に適用されない。`hold` のキーはSWDIOであり、両者を区別する |
| 中 | settings.ja.md「ピンのラベル」の「32文字まで」 | 規範と実装の上限は32 **byte**。非ASCIIを含むラベルで文字数だけを検証すると保存時に失敗する。Web側の検証は符号化後のバイト数を基準にする |

この作業ではガイドのリポジトリを変更していない。Web側は上記の誤記を取り込まない。
`rest` / `hold` の実設定フォームは実機schemaを組み込む段階に残し、配線編集に単なる操作条件として置かない。

### Web製品として維持する判断

- プローブを新たに用意する人への推奨はESP32-P4。ガイドの用途別ボード比較は補足として使う。
- 固定配線を把握していればスキャン不要。ガイドのCLI例にスキャンがあっても、Webの必須工程にしない。
- 導入後は同じ接続を引き継ぐ。用途を選び直すために接続方式やプローブのボードを選ばせない。
- ガイドのCLI操作をブラウザの必須手順へそのまま移さない。Webでの導入・設定と、外部ツールで行う取得・書込等を明示する。
- P4 UART bridgeはfirmwareソースで既定有効になった。サイトの配布ファームウェアへの反映と経路別実機試験は別に確認する。

## 用途から画面へ落とす順序

入口は「何をしたいか」。次に相手側の方式を選ぶ必要がある場合だけ選び、配線を用意する。
本体設定が不要な用途では、設定を保存する画面を通さず操作準備へ進める。

| 利用者の目的 | 先に決めること | 本体に残すもの | 使うときに決めるもの | 到達先 |
| --- | --- | --- | --- | --- |
| CH32を書込・デバッグしたい | 相手の系列に合うRVSWD / 1線DIO（SWIO）、信号ピン、任意のNRST | 繰り返し使うなら配線名。必要な治具だけrest/hold等 | 速度上限、停止して接続するか、NRSTを使うか。通常は道具の既定を使う | Webのデバッグ操作例、書込/GDBはch32rv・Arduinoへ |
| ARM Cortex-Mを調べたい | SWD、SWDIO/SWCLK、任意のNRST | 繰り返し使うなら配線名 | 速度上限、接続条件、必要な相手だけTARGETSEL | SWD操作例・Pythonへ。汎用flash loader/GDB対応とは表示しない |
| UARTログを読みたい・送信したい | 相手TX→プローブRX。送信するときだけTX→相手RX | 配線名は任意 | baud、形式、送受信条件 | UART操作画面。受信専用ならTX不要 |
| デバッグ線でログを扱いたい | RVSWD / SWIOの配線。既存のデバッグ配線を再利用可能 | 配線名は任意 | 相手アプリの出力方式sdi/dmdata/dmseq | コンソール操作例。sdiには送信を出さない |
| 普通のシリアルモニタで見たい | ログの入力元→その配線・条件→出力先シリアルポート | 素通し設定。必要なら現在値全体を永続保存 | モニタ側のポート指定 | 設定後、明示的にOEP利用を終了して外部モニタへ。相手→PCのみ |
| 今回だけ波形を取りたい | 観測するピンとファイル内での信号名 | なし | レート、サンプル数/時間、トリガ・プリトリガ | WireSkeinへの引継ぎ内容確認 |
| デバッグ等の配線を観測したい | 保存済みの配線名を選ぶ | 既存ラベルを再利用。別の観測用ラベルは不要 | 同上 | 同じピンのロジック観測。配線を奪わない |
| 操作中の波形を取りたい・テストしたい | 配線、外部の操作手順・期待値 | ラベルは便利だが取得条件ではない | WireSkein/Pythonで操作と取得・照合を組む | 手順・外部環境への案内 |
| センサ・周辺ICと通信したい | I2C / SPI、配線、通信を始めるのはプローブ | 配線名は任意 | アドレス、クロック、mode、送受信データ | controller操作 |
| 開発中マイコンのドライバを試したい | プローブが応答側になる方式と配線 | 配線名は任意 | 応答アドレス/mode、応答データ、待受 | 相手機器としての操作。現在のプレビューはI2C例 |
| 信号を出す・測る | GPIO/PWM/counter/DAC/analogと使うピン | 必要な場合だけidle等 | 値、周波数、時間等 | 操作例。アナログ取得はWireSkein準備へ |
| 治具として据え置きたい | 使用禁止→配線名→待機状態→任意の素通し→保存・控え | 上記の本体設定。型番・メモは別記録 | 操作時の条件は各道具が指定 | 順番付きの治具設定案内 |
| 離れた場所から使いたい | Wi-Fi対応の宣言を確認、ネットワーク情報 | SSID等、必要ならIP設定 | 外部の対応hostからネットワーク接続 | 非対応プローブにSSIDを入力させない。ブラウザからTCP接続はしない |

### 保存と戻る操作

1. 一度だけ使う場合は操作画面で一時ピンを指定し、動作開始は明示ボタンで行う。
2. 繰り返し使う場合は配線名・相手型番・メモを登録する。保存は接続・出力を開始しない。
3. 新規登録後は準備完了→同じ用途の操作条件へ。既存配線の編集後は呼出元へ戻す。
4. 配線を変えても、ほかの用途の配線を黙って消さない。途中で方式を変える場合は、異なる役割のピンを引き継いだことにしない。
5. 素通しのbaudは本体設定だが、通常UARTのbaudは操作条件。同じ項目名でも保存先と有効な期間を説明する。

## 今回のプレビューと残る範囲

上表の用途分岐、本体設定と操作条件の分離、RXのみのUART、ログの3経路、キャプチャの4つの使い分け、据え置きの順序を画面例として反映する。
ガイドへのリンクを追加し、実機処理は引き続き接続しない。取得条件の控えは画面表示であり、外部ツールへの自動転送ではない。

実機schemaによる候補・範囲・競合の制限、ターゲット系列ごとの自動判定、TARGETSEL、rest/hold、SPI応答側の画面、アナログ専用の全条件、実バックアップ/復元は今後の実装範囲。
CH32のデバッグ線によるシステムリセット（PFIC経由、NRST不要）と、NRSTを使ったattachは別の操作として扱う。今回、新しいリセット実行機能は追加しない。
