# OEP Web — 画面プレビューの確認手順

状態: **画面構成・文言・遷移をレビューする段階**。実機処理は未接続。
用途選択・デバッグ方式別の分岐は検討途中の画面例として保存している。用途別の名称・範囲・設定順序は、別セッションで整理するOEP側のドキュメントをレビューしてから確定・反映する。
[要件定義](page.ja.md)と[接続引継ぎ仕様](page-connection.ja.md)に沿った画面を、サンプル値で操作できる。
プレビュー上の成功は、実機での動作や[受入条件](page-acceptance.ja.md)の達成を意味しない。

## 開き方

リポジトリで `npm run serve` を実行し、`http://localhost:4173/preview/` を開く。
現行画面の「新しい画面プレビュー」からも移動できる。現行画面は引き続き `/` にある。

画面は日本語。上部に常時プレビューの表示があり、機器の選択、書き込み、再許可はすべてデモ操作。
USB接続やudev設定は不要。入力した接続先・設定はタブ内だけに保持され、再読込や「最初からやり直す」で消える。
なお `npm run serve` は現行画面用のfirmwareを初回に取得する。プレビュー自体はそれを読み込まない。

## まず確認する流れ

1. **OEPを知る**: トップで目的と全体像を読み、「できること」「対応ボード」「技術・資料」をたどる。ボードの型番だけでなく、用途・特徴・制約から選べるかを確認する。
2. **新しいプローブを作る**: 推奨のESP32-P4を先頭・初期選択として表示する。書き込み先のデモ選択、内容確認、導入へ進む。完了後に接続方式を選び直さず、初期設定へ進むことを確認する。
3. **ターゲットを接続せず設定する**: 初期設定で利用パターンを選び、名前、相手の型番、メモ、固定ピンと条件を入力する。スキャンは不要。保存後は準備完了の画面から、その用途の操作へ進める。デバッグはSWD・2線RVSWD・1線DIO（SWIO）を選んでから配線を指定する。NRSTは任意。
4. **設定を編集する**: 接続先一覧から同じフォームを開き、型番やピンを変更する。変更中の離脱では、編集を続けるか破棄するかを選べる。
5. **用途に合わせて使う**: UARTなどの操作画面へ移る。画面を開いただけでは操作を開始しない。説明・配線・設定・開始・サンプル結果・停止を確認する。継続する操作は別画面でも使用中と表示され、停止できる。
6. **別の初期設定を選ぶ**: 「本体設定・復元・配線を保存せず試す」と「あとで設定する」の入口も確認する。本体設定では適用と保存を区別する。ロジックアナライザの画面例では4チャネルの配線と取得条件を用意し、WireSkeinの取得環境への案内に進む。
7. **導入済みのプローブを使う**: 最初からやり直し、トップの導入済み向け入口を選ぶ。ボード種類やCDC/UARTを選ばずデモ接続し、作業へ進む。操作画面から接続した場合は、その用途へ戻る。

## 書き込み後の分岐

上部の「確認シナリオ」を押すと、ページ末尾の切替欄が開く。導入開始前にシナリオを選び、書き込み完了後の流れを比較する。

| シナリオ | 確認する表示と遷移 |
| --- | --- |
| 同じポートで自動続行 | 書込成功 → 初期設定。機器や方式を選び直さない |
| 起動後のOEPを再許可 | 書込成功を保持 → 起動したOEPの許可 → 初期設定 |
| USB構成変更 → 抜き差し → 許可 | 書込成功を保持 → 抜き差しが必要な場合の案内 → 許可 → 初期設定 |
| 書込成功 → 接続待ちから再試行 | 書込失敗として扱わず、同じ文脈で接続を待ち直す |

「ボードに応じた流れ」の例は、ESP32/P4が自動続行、Picoが再許可、S3が抜き差し。
これは画面比較用の割当であり、ボードごとの実機挙動を保証しない。VID/PIDが変わっただけで必ず抜き差しが要るという仕様ではない。

## 今回の範囲と、後で実装すること

| 今回確認できるもの | 実処理を組み込む段階で必要なもの |
| --- | --- |
| 入口・用途・ボード説明、資料への導線 | 配布ファームウェアイメージ・実機検証状況に連動した対応表示 |
| 導入・許可・復旧・初期設定の流れ | ROM検出、実書込、同一ポート継続、機器同一性・権限・USB再列挙の処理 |
| 接続先の作成・編集、重複ピン検査、離脱確認 | 実際の機能宣言に基づくピン制約、差分確認、プローブへの保存と部分失敗の復旧 |
| 各用途の入力・開始・結果・停止の配置 | 入力に対応する通信・出力・計測・デバッグ、単位換算と実機での停止確認 |
| 本体設定の適用/保存と保守の入口 | schemaに基づく編集、永続保存、ファイルのバックアップ/復元、firmware更新 |
| WireSkein・IDE・Pythonへの案内 | 実セッションの終了、用途別の引継ぎ情報生成 |

操作結果は固定サンプルで、入力値に応じた計算結果ではない。信号のピン候補も例示。
配線と一緒に入力した通信・取得条件もタブ内のデモ状態であり、プローブに保存される設定形式を定めるものではない。
「I2C / SPIの相手機器になる」は現時点ではI2Cの画面例。ボードを変えた場合の全機能差、接続先の削除、すべての異常系、英語版はまだ含まない。
実機接続時にはプローブの宣言が正であり、このプレビューのボード名や候補を動作判定には使わない。

## 検証

```sh
npm run typecheck
npm run test:preview
```

`test:preview` はサイトをビルドし、一時HTTPサーバとheadless Chromiumで操作を確認する。Python仮想probeは不要。
Chromeの実行ファイルは `OEP_CHROME` で指定できる（既定 `google-chrome`）。
スクリーンショットは `/tmp/oep-preview-review/` に出力する（`OEP_PREVIEW_ARTIFACTS` で変更可能）。

導入後の4分岐、配線の作成・編集・破棄、デバッグ3方式の設定・引継ぎ、UARTの通信条件、ロジック観測の準備、目的別の操作、設定、外部ツールへの案内を確認する。
1440px幅と390px幅で表示し、狭い画面の横方向へのはみ出しも検査する。
実機APIへのアクセスは禁止して検出し、通信・書込モジュールの読込とJavaScript例外がないことを確認する。
本試験は画面の回帰試験であり、実機の接続や書き込みを検証するものではない。
